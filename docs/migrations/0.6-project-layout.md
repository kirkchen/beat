# Migrate a Beat project to the 0.6 project layout

Beat 0.6 moves the glossary from `beat/CONTEXT.md` to `GLOSSARY.md` at the project root and adds three agent docs: `CODING_STANDARDS.md`, `docs/agents/issue-tracker.md` and an `## Agent docs` block in `CLAUDE.md` or `AGENTS.md`.
The layout is defined in https://github.com/kirkchen/beat/blob/main/references/project-layout.md. Paste this document into an agent running inside the project and let it execute the steps below in order.

## Steps

Run every command from the project root. Each step ends with a check; do not start the next step until the check passes.

### 1. Preconditions

```bash
git status --porcelain          # must print nothing
git branch --show-current
```

If the working tree is not clean, stop and ask the user to commit or stash first. If the current branch is the default branch (`main`, `master`, or whatever `git symbolic-ref refs/remotes/origin/HEAD` names), create a branch:

```bash
git switch -c chore/beat-0.6-layout
```

Check: the tree is clean and the current branch is not the default branch.

### 2. Rename the glossary

- `beat/CONTEXT.md` exists and `GLOSSARY.md` does not: `git mv beat/CONTEXT.md GLOSSARY.md`.
- `beat/CONTEXT.md` does not exist: skip this step. Do not create `GLOSSARY.md`; it is created later by the first skill that writes a term.
- Both exist: stop and ask the user which one to keep. Do not merge them yourself.

The file's content does not change apart from the relative links fixed in step 3c.

Check: `test ! -e beat/CONTEXT.md && echo ok` prints `ok`.

### 3. Rewrite references to the old path

**Records are never rewritten.** Records are files that describe what was true at a point in time. This is the list, quoted from the layout reference:

- paths under `beat/changes/archive/`
- paths under `docs/incidents/`, `docs/proposals/`, `docs/research/`, `docs/migrations/`
- the file `CHANGELOG.md`
- any file whose basename starts with a date, matching `^\d{4}-\d{2}-\d{2}-`

A record may keep the old path `beat/CONTEXT.md` forever. Active changes under `beat/changes/<name>/` are not records, even when the change directory name starts with a date; only the file's own basename counts.

**3a. Literal path.** List the tracked files outside the records that contain the old path:

```bash
git grep -l 'beat/CONTEXT.md' -- . \
  ':(exclude)beat/changes/archive/**' \
  ':(exclude)docs/incidents/**' ':(exclude)docs/proposals/**' \
  ':(exclude)docs/research/**' ':(exclude)docs/migrations/**' \
  ':(exclude)CHANGELOG.md' \
  ':(exclude,glob)**/[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]-*' > /tmp/beat-0.6-files.txt
```

In every listed file replace `beat/CONTEXT.md` with `GLOSSARY.md`, for example `xargs perl -pi -e 's{beat/CONTEXT\.md}{GLOSSARY.md}g' < /tmp/beat-0.6-files.txt`. This covers prose, Markdown links written from the root (`../../beat/CONTEXT.md` becomes `../../GLOSSARY.md`, which resolves correctly), config values and code that reads the glossary (a lint script's default path, for example). In `CLAUDE.md` / `AGENTS.md` it also covers grep hints such as `grep -n '^\*\*<詞>' beat/CONTEXT.md`, which become `grep -n '^\*\*<詞>' GLOSSARY.md`; read those two files afterwards to confirm every hint now names `GLOSSARY.md`.

`git grep` does not follow symlinks. If `AGENTS.md` is a symlink to `CLAUDE.md` (or the reverse), edit the target file only and keep the symlink.

**3b. Relative links to the old file.** Files inside `beat/` often link to the glossary without the `beat/` segment, such as `[glossary](./CONTEXT.md)` in `beat/ARCHITECTURE.md` or `(../../CONTEXT.md)` in `beat/features/<area>/README.md`. 3a does not catch them. Find them with:

```bash
git grep -nE '\]\([^)]*CONTEXT\.md' -- beat ':(exclude)beat/changes/archive/**'
```

For each hit outside the records whose target resolves to `beat/CONTEXT.md`, replace the target with the relative path from that file to `GLOSSARY.md` at the root, keeping any `#anchor`: from `beat/ARCHITECTURE.md` it is `../GLOSSARY.md`; from `beat/features/<area>/README.md` it is `../../../GLOSSARY.md`.

**3c. Relative links inside the moved glossary.** `GLOSSARY.md` is now one directory higher than before. In `GLOSSARY.md`, a relative link that started with `../` loses one `../` (`../docs/adr/0032-x.md` becomes `docs/adr/0032-x.md`); a relative link that did not start with `../` gains `beat/` (`ARCHITECTURE.md` becomes `beat/ARCHITECTURE.md`). Leave absolute URLs and pure `#anchor` links alone.

**3d. Bare file name (judgement, optional).** Prose that says just `CONTEXT.md` without the directory is not checked by the validator. List it with `git grep -nw 'CONTEXT\.md'` using the same record excludes as 3a, and change it to `GLOSSARY.md` where it clearly means the project glossary in a living document. Leave it when unsure.

Check: the 3a `git grep` command, run again without the `> /tmp/beat-0.6-files.txt` redirect, prints nothing, and the 3b command prints no hit outside the records.

### 4. `CODING_STANDARDS.md`

If `CODING_STANDARDS.md` exists at the project root, keep it as is. If it is absent, create it with exactly this text:

```markdown
# Coding Standards

For reviewers. Mechanical rules (a banned API, an import shape, a file-location rule) belong in lint, not here. This file holds judgement rules and points at where the project already documents them.

## Sources

<one line per existing conventions document: path — what it governs. Setup fills this by scanning README conventions sections, CONTRIBUTING.md and docs/ files whose name contains convention, standard, style or guideline.>

## Judgement rules

<one rule per line, each with the ADR, README or incident it comes from. `/retro` appends here; `pr-review` enforces from here.>
```

Then fill `## Sources` by scanning:

- `CONTRIBUTING.md`
- `README.md` files at the root and one level under `src/`, `packages/`, `apps/`: headings containing convention, invariant, testing or style
- `docs/**` files whose name contains convention, standard, style or guideline

Write one line per hit, `path — the heading or first sentence`, in place of the Sources placeholder. If nothing is found, leave the placeholder. Leave `## Judgement rules` with its placeholder.

Check: `test -f CODING_STANDARDS.md && echo ok` prints `ok`.

### 5. `docs/agents/issue-tracker.md`

If the file exists, fill only the setup placeholders still in it (`<owner>/<repo>` or `<group>/<project>`, `<assignee>`, `<dispatch-label>`) and keep everything else. If it is absent, pick the template from `git remote -v`:

| Remote host | Template |
|-------------|----------|
| `github.com` | https://github.com/kirkchen/beat/blob/main/references/issue-tracker-github.md |
| `gitlab.com` or a self-hosted `gitlab.*` | https://github.com/kirkchen/beat/blob/main/references/issue-tracker-gitlab.md |
| any other host, or no remote | https://github.com/kirkchen/beat/blob/main/references/issue-tracker-other.md |

Ask the user when remotes point at more than one host, or the host may be a self-hosted GitHub or GitLab. Fetch the template (raw form: replace `github.com/kirkchen/beat/blob/main` with `raw.githubusercontent.com/kirkchen/beat/main`) and write it to `docs/agents/issue-tracker.md` (`mkdir -p docs/agents`). Then fill:

- `<owner>/<repo>` (GitHub) or `<group>/<project>` (GitLab): from the remote URL. For the "other" template, ask for `<tracker name>` and `<tracker location>` instead, and ask for the one-paragraph Conventions description (leave its placeholder if the user has none).
- `<assignee>`: ask the user which account the orchestrator runs as (the login that will own the PRs).
- `<dispatch-label>`: `rhythm-change` unless the user wants another label. When the value is `rhythm-change`, delete the "(default `rhythm-change`)" note after it in the Vocabulary row.

Every other `<...>` in the template (`<number>`, `<file>`, `<parent>`, `<n>`, and so on) is a command argument filled at run time: leave it as written.

The Vocabulary and Epics sections are fixed across projects. For GitHub they read as follows, and the written file must contain them verbatim apart from the `<assignee>` and `<dispatch-label>` edits. If you cannot fetch the template, write the title `# Issue tracker: GitHub`, the line ``Issues for this repo live in `<owner>/<repo>` on GitHub. Use the `gh` CLI for all operations.``, and these two sections, then tell the user the Conventions section is missing.

```markdown
## Vocabulary

| Term | Value | Meaning | Set / cleared by |
|------|-------|---------|------------------|
| Dispatch label | `<dispatch-label>` (default `rhythm-change`) | A command: adding it dispatches the issue, the orchestrator removes it. | Added by a human (or `/beat:to-issue` when the user asks in words); removed by the orchestrator |
| Assignee | `<assignee>` | The account the orchestrator runs as. Required: a missing assignee is rejected. | Set when the issue is created |
| `status/ready` | label | Specified and waiting for dispatch. | Set by `/beat:to-issue`; cleared by the orchestrator on dispatch |
| `status/running` | label | A run is working on the issue. | Set and cleared by the orchestrator |
| `status/waiting` | label | The run stopped at a gate and is waiting for a human answer. | Set by the orchestrator at a gate; cleared on reply |
| `status/blocked` | label | The run failed or hit a policy stop. | Set by the orchestrator on failure or policy; a human clearing it re-dispatches |
| `status/in-review` | label | The PR is open and awaiting review. | Set by the orchestrator when the PR is open; closed by the merge |

The five `status/*` labels are mutually exclusive. An open issue with none of them is backlog. `type/*` and `priority/*` labels are orthogonal and not part of the flow.

## Epics

A too-big exploration is an epic issue whose body comes from `beat/routes/<route>/route.md`. Each change node is a sub-issue whose first body line is `Route: <route>/<node>`. A `blocked_by` edge in the route becomes a native blocked-by link. A node is dispatchable when it has `status/ready` and no open blocker.
```

The GitLab and other templates use the same five `status/*` labels; take their exact wording from the fetched file.

Check: the file exists and `grep -nE '<(owner>/<repo|group>/<project|assignee|dispatch-label)>' docs/agents/issue-tracker.md` prints nothing (for the "other" template, `<tracker name>` and `<tracker location>` are filled too).

### 6. `## Agent docs` block

Pick the file: `CLAUDE.md` if it exists, else `AGENTS.md` if it exists, else ask the user which one to create (`CLAUDE.md` for Claude Code, `AGENTS.md` for Codex and other agents). If one is a symlink to the other, edit the target. Add this block; if the file already has an `## Agent docs` heading, replace that section's lines in place instead of adding a second block:

```markdown
## Agent docs

- Glossary: `GLOSSARY.md` — canonical terms; use them in every artifact.
- Coding standards: `CODING_STANDARDS.md` — judgement rules reviewers enforce; mechanical rules live in lint.
- Issue tracker: `docs/agents/issue-tracker.md` — where issues live, labels, how work is dispatched.
```

The block points at `GLOSSARY.md` even when the glossary does not exist yet. Do not create `GLOSSARY.md` to satisfy it.

Check: `grep -n '^## Agent docs$' CLAUDE.md AGENTS.md 2>/dev/null` prints exactly one line.

### 7. Run the layout validator

The validator is `scripts/validate-beat.mjs` from Beat 0.6 or later. It is a single file that needs Node 18+ and no packages. Find it in one of these places:

- the Claude Code plugin cache: `ls ~/.claude/plugins/cache/*/beat/*/scripts/validate-beat.mjs` and take the highest version, 0.6.0 or later;
- a local clone of https://github.com/kirkchen/beat;
- otherwise download it: `curl -fsSL https://raw.githubusercontent.com/kirkchen/beat/main/scripts/validate-beat.mjs -o /tmp/validate-beat.mjs`.

```bash
node <path-to>/validate-beat.mjs --layout
```

Errors cover a missing `docs/agents/issue-tracker.md` or `CODING_STANDARDS.md`, a missing `## Agent docs` heading, a leftover `beat/CONTEXT.md`, and tracked files outside the records that still reference `beat/CONTEXT.md`. Fix each error with the step it belongs to and run again. Missing `GLOSSARY.md` and `docs/adr/` are warnings: both are created on first need, so leave them. Records keeping the old path are not reported and must not be edited.

Check: the last line of output is `layout ok`.

### 8. Project doc linters

Run whatever the project uses to check documentation and links (`pnpm lint:docs`, `npm run lint:docs`, `make lint-docs`, a markdown link checker; look in `package.json`, `Makefile` and the CI config). Broken relative links after the move usually mean a case from step 3b or 3c was missed. If the project has a script that reads the glossary (a feature linter that parses glossary terms, for example), run it too to confirm it now reads `GLOSSARY.md`.

Check: every doc linter the project runs exits 0.

### 9. Commit

Stage the changes from steps 2–6 and make one commit:

```bash
git add -A
git commit -m "chore(beat): migrate to 0.6 project layout"
```

Do not push. Open the pull request the way the project normally does, or leave that to the user.

Check: `git status --porcelain` prints nothing and `git log -1 --format=%s` prints `chore(beat): migrate to 0.6 project layout`.

## What this does not do

- No symlink from `beat/CONTEXT.md` to `GLOSSARY.md`. Skills read only the new path.
- No `GLOSSARY.md` is created when `beat/CONTEXT.md` did not exist, and no `docs/adr/` is created.
- No edits to records: archived changes under `beat/changes/archive/`, `CHANGELOG.md`, incident / proposal / research / migration docs, and date-prefixed files keep `beat/CONTEXT.md`.
- No labels are created on the tracker. Creating `status/*` and the dispatch label is part of the orchestrator's setup.

## Checked against

Dry run on 2026-11-04 against a fresh `git clone --depth 1` of a real Beat project (rhythm: a GitHub remote, a 2,000-line glossary at `beat/CONTEXT.md`, `AGENTS.md` symlinked to `CLAUDE.md`), steps 2, 3 and 7 by hand, steps 4–6 stubbed with the template files:

- Before: `--layout` reported 61 errors (57 files still referencing `beat/CONTEXT.md`, the leftover `beat/CONTEXT.md`, and the three missing agent docs).
- Step 3a rewrote 56 files; `AGENTS.md`, the 57th file in the validator's list, was fixed through its symlink target `CLAUDE.md`. Step 3b fixed relative links in 7 files (one of them not in the 3a list), step 3c fixed 3 links inside `GLOSSARY.md`. Without 3b and 3c, `--layout` still passed but the project's doc linter reported 12 broken links; 3b and 3c were added to this document because of that. 17 files outside the records had bare `CONTEXT.md` prose (3d), which the validator does not check.
- After: `--layout` printed `layout ok` with no warnings (`GLOSSARY.md` and `docs/adr/` both existed), and the project's doc linter passed.
